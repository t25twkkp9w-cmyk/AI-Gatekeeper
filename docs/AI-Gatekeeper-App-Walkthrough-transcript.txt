Welcome and business context
Welcome to the AI Gatekeeper application walkthrough. Imagine a healthcare team proposing an AI assistant. Governance reviewers need evidence, approved tooling and accountable decisions, but manual handoffs create gaps and delays. We will tour the workspace, then follow three real local workflows. This is an edited capture of an interactive session using synthetic data and rule based execution, not a live language model demonstration.

Feature tour  |  Dashboard and intake
The dashboard brings the portfolio and review status together. New assessment opens the intake form. The requester declares an owner, purpose, data classification, tool and system version. Clinical use, patient facing output and external processing are explicit flags. These declarations determine later evidence requirements. We close the form and use seeded cases for this demonstration.

Feature tour  |  Sources and portfolio
The policy library exposes versioned internal rules and the approved tools register. This makes the assessment basis visible to reviewers. The assessment portfolio supports searching and status filtering. Inside each case, Assessment, Evidence, Decision and Activity organize the work. Monitoring and Audit provide cross case visibility, which we will inspect after running the scenarios.

Use case 1  |  Run the staff assistant assessment
Our first proposal is a staff policy knowledge assistant. It uses internal data and an approved tool, with oversight evidence already present. We select Run assessment. The saved workflow inspects evidence, checks the register and maps policy requirements. The result is low risk and ready for AI Governance review. The business value is a prepared review packet, not automatic approval.

Observe the actual tool results
Open Activity to see what actually executed. Evidence inspection found one matching evidence kind and no gaps. Lookup tool returned Northstar Assist as approved. The risk step produced a finding grounded in versioned policy. Review preparation then paused for a human decision. These are recorded tool results and state transitions, not generated explanations of hidden model reasoning.

Human handoff  |  Verify and decide
The Business Requester cannot approve. Switching to Governance Reviewer enables evidence verification and sign off. We check the oversight record, attest AI Governance review and enter a scope specific rationale. Approve scope records the outcome and preserves the verified checks. Export packet is available for the case record. The approval concerns this synthetic proposal and does not deploy any system.

Use case 2  |  Patient messages need evidence
Patient message drafting introduces protected health information, patient facing output and an external processor. Running the assessment now produces a different route. The workflow pauses for BAA, evaluation and monitoring evidence. It retains the case rather than filling gaps with assumptions. This is a practical agentic behavior: stop, explain the missing inputs and wait for the next authorized action.

Supply evidence and resume
The Evidence workspace identifies missing artifacts. We select Add demo evidence to attach explicitly synthetic fixtures. Their metadata includes author, date and system version. Resume assessment rechecks completeness and continues the same case. It now reaches high risk review with AI Governance, Privacy and Security or Vendor Risk. Evidence presence does not remove the human decision gate.

Inspect the source behind a finding
Opening the policy citation reveals the exact fictional clause behind the finding. The reviewer can compare the requirement with the submitted evidence. This connects the result to a source instead of asking the reviewer to trust a fluent summary. The current evidence tool checks metadata and version, so people still need to verify content and scope.

Use case 3  |  A tool becomes unavailable
Discharge instruction drafting has complete evidence, but its tools register deliberately fails. We run the assessment and open Activity. Two lookup attempts fail, then the workflow pauses with the case saved. It does not interpret an unavailable register as approval. This scenario tests bounded retries and a visible recovery path for the person operating the system.

Retry and inspect preserved history
Select Retry lookup. The synthetic outage clears, and the same checkpoint resumes. The trace keeps both failed attempts, then adds the resume event, successful lookup, high risk assessment and review preparation. We can explain what changed and why the workflow continued. A human decision is still required after recovery.

Monitoring audit and the model boundary
Monitoring shows eighteen workflow events, two failed tool attempts and one human decision. Audit records the actions and rationale. In this tested mode, rules select the workflow path and real local tools execute. Optional live mode adds bounded model selected tool loops and advisory summaries. Live model and LangSmith integration still need credentialed validation. This demonstration proves local state, tool use, interruption, recovery and human handoff, while preserving decision accountability.

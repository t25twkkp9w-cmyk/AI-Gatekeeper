01 Executive Summary

AI Gatekeeper Agent supports enterprise review of proposed AI use cases before approval. It gathers case context, checks required evidence, verifies tool eligibility, assesses risk, and prepares a policy-grounded packet for a human reviewer.

The demonstration uses Northstar Health, a fictional healthcare organization. Next.js and FastAPI provide the application, LangGraph coordinates stateful workflows, LangChain specialists use OpenAI models and tools, and LangSmith exposes execution. Application rules enforce approval restrictions; agents explain findings and prepare recommendations.

The workflow pauses for missing evidence, recovers from tool failures, and reassesses requested changes. A recorded human decision ends the process. Approval does not deploy an AI system.

02 Problem Statement

AI governance reviews often depend on email, spreadsheets, scattered policies, and repeated follow-ups. Reviewers must establish what a system does, which data it handles, whether its tool is permitted, and what evidence supports the proposal. Incomplete requests delay review, while inconsistent interpretation makes decisions harder to explain.

ExampleBusiness contextGovernance need
Staff policy assistantEmployees search internal operating policies.Check approved tool use, data scope, and oversight.
Patient message draftingAn external tool drafts messages using protected health information.Check privacy, evaluation, monitoring, and human review evidence.
Autonomous prescribingAI would make prescribing decisions without clinician approval.Detect prohibited use and block approval.

The intended value is more complete submissions, consistent rule application, and traceable decisions. Review-time savings have not yet been measured.

03 Scope

  • Capture use-case context and maintain case records.
  • Check evidence completeness and version alignment; retrieve policy clauses and tool records.
  • Assess risk, prepare review material, and enforce approval gates.
  • Pause and resume for evidence, recovery, requested changes, and decisions.
  • Record case history, provide exports, and trace execution with LangSmith.

Outside the current scope: real patient data, independent evidence verification, live vendor integrations, enterprise SSO, tamper-proof audit storage, and deployment of approved AI systems. Policy retrieval is by identifier; vector search and embeddings are not implemented.

The agent at the center

Inputs establish the case. The agent coordinates model reasoning and read-only tool calls. Tool observations come from versioned knowledge and case evidence. Outputs support a human decision. Application rules enforce the boundaries, and LangSmith traces execution.

05 Enterprise Workflow

The enterprise process starts with an AI use request and ends with a recorded human decision. Requesters supply context and evidence. Reviewers examine the packet and record approval, rejection, or requested changes.

Approval requires the application gates to pass. A persona selector demonstrates role-based action gates but does not establish an independently verified user identity.

06 Agentic Workflow and Runtime Flow

LangGraph controls the outer process. Intake checks required evidence. A complete case proceeds to tool lookup, risk assessment, and review preparation. Missing evidence produces an interrupt. A failed register lookup allows two total attempts before an explicit recovery pause. Requested changes return a revised case to intake for reassessment.

All three specialists use MODEL OpenAI through LangChain. Their outputs cannot override deterministic blockers. Checkpoints support resumption; case data and application audit history record the business context.

11 External Systems and Observability

OpenAI supplies model inference, LangSmith captures traces, Render hosts the app, and GitHub stores source code. Policy and approved-tool lookups read the synthetic catalog rather than live enterprise services.

  • Locate the case run in the corresponding LangSmith project.
  • Expand workflow and specialist spans to inspect model inputs, outputs, and tool activity.
  • Review latency, token usage where available, failures, and fallback behavior.
  • Compare the trace with the application workflow and audit history.

A previously verified local live run included three specialists, six model spans, and seven tool spans without reported errors. Counts can vary by run. Hosted health checks showed live-mode configuration and tracing enabled; authenticated hosted execution and its corresponding trace still require end-to-end verification.

12 Human in the Loop Boundary

Human review is an explicit interrupt. The application checks the reviewer persona, evidence, required attestations, and rationale. Approve and reject record final outcomes; request changes pauses for revision and reassessment. Prohibited-use blockers prevent approval.

Shared credentials and selectable personas are demonstration controls. They do not independently authenticate each reviewer or signoff. An enterprise version needs individual identity and stronger authorization.

13 Setup and Runbook

  • Obtain repository access and follow its current backend and frontend installation instructions.
  • Create the local environment file from the supplied example and configure OpenAI and LangSmith credentials.
  • Start the services using the repository launch instructions; check the application and health endpoint.
  • Run a synthetic case and inspect the matching LangSmith trace.

The hosted Docker container includes Nginx, Next.js, and FastAPI. Nginx routes UI and API traffic and enforces shared password protection. The health endpoint is public for service checks.

Render Free uses ephemeral storage: case records, audit history, and checkpoints can be lost on restart or redeployment. Export results that need retention. Allow for cold-start time before a demonstration.

17 Iterations and Learnings

Anchor technology to the enterprise workflow. Submit, gather, assess, review, and decide makes the purpose of each component clear.

Separate reasoning from enforcement. Models improve explanations while explicit rules maintain decision boundaries.

Design for interruption. Evidence gaps, requested changes, and unavailable tools are normal governance work. Durable state and resumption are central behaviors.

Show actual execution. A LangSmith trace connects the architecture to real model and tool calls. Hosting success alone does not validate those calls.

18 Extension Points

  • Enterprise SSO, individual reviewer authorization, and independently authenticated signoffs.
  • Durable managed storage, backup and recovery, and tamper-evident audit records.
  • Live policy and tool-register integrations with stronger evidence provenance checks.
  • Automated evaluations for policy grounding, explanations, and tool selection.
  • Operational monitoring for latency, failures, and cost; measurement of review time and reviewer effort.

These are proposed enhancements, not current capabilities.

19 Current Implementation Boundary

AI Gatekeeper Agent demonstrates stateful AI governance using synthetic data: submit a case, inspect evidence, check tool eligibility, assess risk, prepare review, obtain a human decision, and retain the history. Agentic behavior includes tool use, conditional routing, checkpoints, interruption, recovery, and human handoff. LangSmith provides execution visibility.

The current shared authentication, synthetic reference data, and ephemeral hosted storage suit a cohort demonstration. Additional work is required for enterprise production use.
